# Plan 027: 2.12.3 — in-app updates for ad-hoc signed releases

- **Status**: DONE — v2.12.3 published; end-to-end update from 2.12.2 to 2.12.3 verified
- **Created**: 2026-09-29
- **Base**: `master` after v2.12.2
- **Target release**: `v2.12.3`

## Problem

`UpdateManager` trusted a downloaded update only if its Team ID matched the running app's.
Ad-hoc signed builds have no Team ID, so every fork release from 2.10 onward refused to
auto-install: "Cannot determine current bundle Team ID; refusing to auto-install." This was
observed in Plan 026 Phase 3. The owner has no Apple Developer Program membership, so Developer
ID signing is not an option.

## Decision (user, 2026-09-29)

Trust a download by checking it against the SHA-256 digest that GitHub publishes for the
release's `zMD.dmg` asset, plus the app's identity and signature.

## Design

1. **Check.** Record `zMD.dmg`'s `browser_download_url` and its `digest` (`sha256:<hex>`) from
   `releases/latest`, preferring the asset named exactly `zMD.dmg`.
2. **Before downloading.** Refuse if the release publishes no SHA-256; the user can download
   manually instead. The downgrade and HTTPS guards are unchanged.
3. **After downloading, before mounting.** Hash the DMG in 1 MB chunks and compare it with the
   published digest. Refuse on mismatch.
4. **After mounting** (`-nobrowse`, unchanged), `trustVerdict` requires:
   - a strictly valid code signature, ad-hoc included;
   - the same `CFBundleIdentifier` as the running app;
   - `CFBundleShortVersionString` equal to the announced release version;
   - the same Team ID only when the running app has one, as for Developer ID builds. Ad-hoc
     builds rely on the digest.
5. The install and relaunch path is unchanged: staged copy, swap into `/Applications`, detach, and
   the relaunch trampoline.

**Trust anchor:** the fork's GitHub releases over HTTPS, the same trust as a manual download from
the release page. The digest check catches corrupt, truncated, or swapped downloads, and the
bundle checks keep another app or version from being installed. It does not protect against a
compromised GitHub account; only a Developer ID Team ID could.

**Rollout:** only builds that contain this code can auto-update. Installs of 2.10.0–2.12.2 must
install 2.12.3 manually once. The 2.12.3 release notes say so.

## Verification

- Unit tests (`UpdateVerificationTests`):
  - digest parsing;
  - asset selection;
  - a known SHA-256 file vector;
  - trust verdicts for ad-hoc and Developer ID cases.
- **End to end.** Build this code locally labelled 2.12.2 (a `MARKETING_VERSION` override) and
  install it into `/Applications`. Then use zMD → Check for Updates to update to the published
  2.12.3, relaunch, and confirm `/Applications/zMD.app` is 2.12.3.
